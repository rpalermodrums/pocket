# Explicit passages in a long recording

Run `python examples/audio-regions/example.py` with Pocket installed in a POSIX environment. It needs the normal audio dependencies, no model or DAW. It creates a new temporary directory containing a synthetic one-hour, 8000-Hz mono PCM16 recording (about 58 MB), artifact store and report. Nothing is downloaded or uploaded.

Three explicitly chosen four-second passages begin at 10, 30 and 58 minutes. The example stream-verifies the original recording and retains exact PCM for each passage, compares inline capture/analysis with independently composed calls, adds an attributed span in original-source coordinates, and queries both local evidence and original-frame projections. A real background worker repeats the final analysis through the same public primitive and must return the identical artifact. Source bytes and filesystem stamps are checked afterward.

The recording is repeated synthetic clicks. Its one-hour duration tests explicit passage positioning; it is not a musical set or an accuracy/listening test. Independent tests separately cover a 635-MB recording and a crop beyond 500 MiB. The capture profile accepts PCM16/24 and ordinary IEEE FLOAT32 RIFF WAV up to two hours and 4 GiB minus one byte, with each passage limited to 20 seconds and 32 MiB. The original remains externally retained; the store contains selected PCM and its original identity/mapping, not an archived full recording.

All steps are independently callable through public Python, the corresponding `pocket audio-region-* --spec request.json` commands and identically named MCP tools. `audio_region_submit` establishes its durable job and execution lease before it hashes an inline long source. Use `job_status` for fresh state and `job_cancel` with its exact revision. Cancellation is cooperative, observed between capture blocks and analysis/publication boundaries; an in-progress decoder may finish first. A cancelled, failed or interrupted job has no committed result and is never retried automatically.

Authored corrections declare either `local_crop_frame` or `original_source_frame`. Their evidence pointers and superseded annotation IDs still address the underlying local analysis. A pulse lattice keeps a local floating estimate beside an exact rational original offset; the wrapper never turns that estimate into exact global timing. Raw detector/model evidence and prior alternatives remain intact. No automatic phrase, note, key, kick, instrument or listener preference is inferred.

FLOAT32 passages retain exact sample bytes with no clipping or integer conversion. NaN or infinity in the selected passage refuses. Capturing a format does not qualify it for every optional analyzer; learned pulse analysis still requires its documented PCM16 profile.
