# 0.4: Baste and Pipette

Baste adds the first real read-only bridge from Pocket into an open Live session.
Its editable Max for Live device reads tracks, both clip views, nested devices and
exposed parameters, with fresh request timing and explicit failure dispositions.
Runtime IDs never become saved-file handles.

Pipette closes a saved Stitch trial's lineage after an explicit keep decision. It
rechecks the trial, candidate, selected render, media and unchanged parent; writes
a new collected child; proves only declared dependency hints changed; seals the
parent/trial/candidate/child chain; and validates through normal Thread handles.

New MCP names: `baste`, `baste_build_device`, `pipette`, `pipette_validate`.
CLI and Python call the same providers. Existing aliases, serialized identifiers,
trials, caches and selection sessions remain unchanged.

Read [Baste setup](../baste.md), [Pipette inputs](../pipette.md),
[the implementation plan](../baste-pipette-plan.md) and
[the acceptance record](../baste-pipette-acceptance.md). The acceptance record
records passing automated/package checks and completed native checks, including
the measured large-set latency limit. This is a local development version, not
a published release.
